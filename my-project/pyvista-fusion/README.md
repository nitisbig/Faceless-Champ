# Nuclear fusion plasma

20 seconds, pure black background, graphics only, silent. A translucent toroidal
chamber surrounds nested cyan magnetic field lines and a pink-to-gold plasma
volume. Ignition builds into traveling density waves and a broad energy pulse;
the camera slowly orbits before the composition fades to black.

Run from the repository root using native Python:

```bash
.venv/bin/python my-project/pyvista-fusion/render.py
```

Default output: `output/pyvista-fusion.mp4` beside this script, 1080p at 30 FPS.
Use `--overwrite` to replace an existing output.

```bash
# Short motion check: source time 10–11 seconds.
.venv/bin/python my-project/pyvista-fusion/render.py --preview --quality 720p --fps 12

# Still frame, custom source range, or full 4K export.
.venv/bin/python my-project/pyvista-fusion/render.py --frame 15.5 --quality 720p
.venv/bin/python my-project/pyvista-fusion/render.py --range 4 6 --quality 720p
.venv/bin/python my-project/pyvista-fusion/render.py --quality 4k
```

PyVista owns an offscreen VTK window, a persistent `ImageData` volume rendered
with `add_volume()`, and transparent isosurfaces generated by `contour()`.
The analytic scalar field is updated in place at each source time. Seeking is
deterministic and independent of export FPS. The grid resolution stays fixed
across output sizes. Magnetic lines and density waves are illustrative; this
is not an MHD simulation or a calibrated fusion-energy model.

A project-local implementation of Faceless Champ's `Renderer` protocol connects
PyVista frames to the library's `Scene`, `ExportSettings`, `ExportProgress`, and
MP4 export pipeline. The current ArchChamp mesh API does not expose volume
rendering, so this example does not modify core APIs. Uses the existing `.venv`
with PyVista, NumPy, Matplotlib, Pillow, and FFmpeg; no Docker or downloaded assets.
API references: [add_volume](https://docs.pyvista.org/api/plotting/_autosummary/pyvista.plotter.add_volume)
and [contour](https://docs.pyvista.org/api/core/_autosummary/pyvista.datasetfilters.contour).

Verification is limited to scalar/seek checks, representative stills and a
one-second preview. Full 20-second export is intentionally unrun. Each render
writes a JSON sidecar recording source range and the actual VTK window type;
`full_export_verified` remains false until a full export is separately checked.
